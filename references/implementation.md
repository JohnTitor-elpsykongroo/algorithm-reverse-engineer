# 工程分析检查表

按所选路径逐项判断；不适用项给原因，不要求所有仓库都有同样机制。

| 检查面 | 必须回答 | 易错点 |
|---|---|---|
| 真实入口 | CLI/脚本/API/Notebook 如何触发？配置合并、默认值、环境变量和覆盖顺序？最终值？ | 库默认值不等于入口生效值；Notebook 隐藏状态 |
| 执行链 | 条件、循环、注册、动态派发、继承覆盖、回调、跨语言如何选择实现？ | 符号存在不等于被调用；备用实现混入主流程 |
| 核心计算 | 包装层下的实际算子？第三方/扩展/编译项/设备后端？ | 根据 API 名猜公式；不同后端假定等价 |
| 数据契约 | 含义、形状、类型/精度、单位、坐标、索引、有效性、别名、生命周期？ | 忽略归一化轴、排序后映射、原位更新 |
| 场景 | 训练/推理/评估、离线/在线共享哪些表示/参数/状态？ | 把训练增强加入推理，串联互斥分支 |
| 敏感细节 | 初始化、随机源、阈值、权重、归约、更新顺序、停止、失败回退？ | 因代码少或称工程优化而忽略 |
| 输出 | 后处理、过滤、反变换、排序并列、索引/坐标恢复？ | 在核心算子结束处停止追踪 |

建立关键变量的 `输入表示→变换→新表示→消费者→生命周期`。保留排序、采样、归一化、过滤及映射。边界验证可选空输入、重复/并列值、退化几何、阈值恰等、无候选、NaN/Inf、最大迭代或缺资源，依据代码选择，不机械穷举。

README、测试、注释和论文只提供线索。文档说 A、实际选 B 时分别记录；算法正文服从 B 的代码证据。无法取得依赖源码时给已知接口、未明行为及影响，不虚构内部计算。完成标准是关键状态变化和输出来源可解释，缺口定位且有影响说明。
