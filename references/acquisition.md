# 获取、范围与续接

## 固定来源

- 区分现存本地目录和远程地址，不能误判 Windows 盘符。确认 Git 根；非 Git 源码可用来源、文件清单和哈希替代 commit，注明版本不可独立核实。
- 本地默认分析当前工作树：记录 HEAD、分支、暂存/未暂存/未跟踪/删除内容及相关文件 SHA-256。保留用户修改，不 checkout、reset、clean 或擅自补子模块。忽略文件、LFS、权重、生成代码若参与计算，另外核对。
- 分析其他版本用隔离副本，不切换用户工作树。复制脏文件时记录，不冒充纯 commit；不要悄悄丢掉当前修改。
- 远程优先取得固定源码，核实 ref 实际解析的完整 commit；不混用移动分支网页或不同版本文件。只执行所需 clone/fetch，不 push。不绑定托管商；SSH/私有地址依赖现有授权与网络。
- 只能取得部分网页/归档时列已取得文件、来源 URL、版本可靠程度和缺失影响。网页可读不等于 Git clone 成功，本地 bare 或 `file://` 不等于真实网络测试；获取失败与替代方式如实记载。

## 基线必须记录

来源（凭据脱敏）、分析时间/时区、commit 与工作树指纹；算法清单、本次入口/命令/配置/场景、覆盖与排除项及理由；用户指定/静态推定/实际运行路径；影响行为的依赖、编译项、运行时、子模块 commit、权重/资源；环境可验证与不可验证项。锁文件声明与实际加载版本分开。

快照脚本只收集 Git 身份，不代替配置、依赖、资源和算法选择。默认输出放仓库外，以免输出文件改变分析对象。

## 选择范围

先列独立算法/入口，不必深挖所有无关路径。根据用户目标、主要公开入口和仓库证据选择，并列出剩余项。只有选择同等合理、会显著改变对象且无法推定时才问。默认、可选、实验、弃用路径分列，不由 demo 名字推定其代表性。

## 旧报告与长任务

检查已有报告的 commit、脏文件哈希、配置、后端、权重；抽查入口可达性、核心运算和关键边界结论。标出可复用/失效结论，版本不同先定位差异影响再补查，避免机械重做。

在工程报告保存已解释执行链、证据位置、未解问题及影响、下一步和临时目录登记。恢复前重新比对身份。交付报告和最小复现证据保留；临时日志/缓存/副本摘要后清理，用户要求保留的资料除外。
